# Anywhere

## Register

product

## Users

Developers who need to interact with AI coding agents (opencode ACP) remotely from their phone. They're already at a computer running the agent; the phone is a secondary interface for quick queries, reviewing output, or initiating tasks when away from the keyboard.

## Product Purpose

A mobile chat interface that connects to any ACP-compatible AI coding agent running on a remote machine. Bridges the gap between desktop agent workflows and mobile convenience. Success looks like: a developer can open the app, select a workspace, send a prompt, and get an agent response without thinking about the underlying protocol.

## Brand Personality

Professional, precise, secondary. This is a tool that stays out of the way. Three words: **clean, sharp, invisible**. Voice is direct — no personality flourishes, no brand voice in UI copy. The app chrome should feel like a well-made instrument, not a destination.

## Anti-references

- Generic SaaS dashboards (pastel gradients, heavy cards, rounded everything)
- Chat apps with "fun" personalities (emojis in UI copy, colorful avatars, message reactions)
- Dark-first "cyber" aesthetics (it's a phone app used in varied light)
- Over-designed toolbars with icons for everything

## Design Principles

1. **Information density first.** Every pixel of screen real estate is valuable on a phone. No decorative spacing, no illustration-for-the-sake-of-it, no empty states with mascots.
2. **Protocol honesty.** The app is a window into an ACP agent session. Don't hide that behind abstractions. Show thinking, tool calls, and plan entries as first-class citizens, not hidden details.
3. **Zero chrome.** The navigation bar, session picker, and input area should recede. The content — messages — is the only thing that should draw attention.
4. **Familiar chat conventions where they help, break them where they don't.** Use the typical user-left/agent-right bubble layout, but don't hide technical details behind chat-like abstractions.

## Accessibility & Inclusion

Target WCAG 2.1 AA. Phone usage means varied lighting conditions — text contrast must hold in sunlight. No reliance on color alone for status indicators (tool call status uses icons + text + color).
